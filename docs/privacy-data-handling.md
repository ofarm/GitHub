# docs/privacy-data-handling.md — データ分類とデータ管理

> 表現上の注意: 「一切保持されない」等の**断定を避ける**。アプリ側で制御できることと、API 事業者側の条件（保持可能性・ZDR）を分けて記述する。最終的な事実は OpenAI の最新公式ドキュメント・契約で確認すること（本書末尾の「確認事項」）。

## 1. データ分類表

| データ | 生成元 | 通過先 | アプリ側で保存 | 保存期間 | ログ出力 | マスキング | 残余リスク |
|---|---|---|---|---|---|---|---|
| 音声（マイク） | ブラウザ | ブラウザ → (WebRTC) → OpenAI | しない | なし | 不可 | N/A（保存しない） | OpenAI 側で短時間処理。ZDR 未承認だと abuse 監視ログに一時保持され得る |
| 入力英語 transcript | OpenAI | OpenAI → (WebRTC data ch) → ブラウザ表示 | しない | 画面表示中のメモリのみ | 不可 | 必須（出力禁止） | 同上（API 事業者側） |
| 日本語翻訳結果 | OpenAI | OpenAI → ブラウザ表示 | しない | 画面表示中のメモリのみ | 不可 | 必須（出力禁止） | 同上 |
| 認証情報（OAuth トークン等） | OAuth プロバイダ | プロバイダ ↔ サーバー（Auth.js） | セッション cookie のみ（HttpOnly） | セッション有効期間 | 不可 | 必須 | cookie 窃取（HTTPS / SameSite で緩和） |
| メールアドレス | OAuth プロバイダ | サーバー（allowlist 照合） | しない（MVP は DB 無し。セッション内のみ） | セッション期間 | 不可（平文） | 必須 | セッション内に存在。ログに出さない |
| 匿名化ユーザー識別子（hash） | サーバー（`SAFETY_ID_SALT` でメールをハッシュ） | サーバー → OpenAI（Safety-Identifier） | しない | なし | 識別子のみ可（本文と紐付けない） | 推奨 | ソルト漏洩時の再識別（ソルトを秘密管理） |
| client secret（`ek_...`） | OpenAI（サーバー経由で発行） | サーバー → ブラウザ → OpenAI | しない（メモリのみ） | TTL（既定 120秒） | 不可 | 必須 | 短命だが窃取時に有効期間内で悪用可。TTL 短縮で緩和 |
| 標準 API key | 環境変数 | サーバー内のみ | secrets として | デプロイ環境管理 | 不可（絶対） | 必須 | 露出時に全 API 悪用。ブラウザに出さない / `.env` 非コミット |
| アプリケーションログ | サーバー / クライアント | デプロイ先のログ基盤 | メタデータのみ | プラットフォーム既定 | 本文以外のみ | 本文除外 | 設定ミスで本文混入 → コードレビューで防止 |
| インフラログ（CDN/エッジ） | デプロイ基盤 | デプロイ事業者 | 事業者管理 | 事業者既定 | URL/メタのみ | クエリに本文を載せない | 事業者保持。本文を URL/ヘッダに載せない設計で緩和 |

## 2. 保存しないデータ（明示）

音声、入力英語 transcript、日本語翻訳結果、会話内容。これらは **DB・ファイル・ログ・ブラウザストレージのいずれにも保存しない**。画面表示はメモリ上のみで、Clear / リロード / タブ閉じで消える。

## 3. 保存しうるメタデータ（許容範囲）

- 認証セッション（HttpOnly cookie）。
- イベント種別・タイムスタンプ・HTTP ステータス・エラーコード（本文を含まない）。
- 匿名化ユーザー識別子（ハッシュ。本文と紐付けない）。
- レート制限カウンタ（識別子 + 回数）。

## 4. 責任分界（アプリ側 / API 事業者側）

- **アプリ側で保証できること**: 本文を保存しない・ログに出さない・ブラウザに保存しない・標準キーを露出しない・許可者のみ利用可。
- **API 事業者側に依存すること**: OpenAI の処理・保持・abuse 監視の挙動。アプリ側はこれを変更できないため、設定（ZDR / Modified Abuse Monitoring）と契約で対応する。

## 5. 学習利用と保持に関する前提（要確認・断定しない）

最新の OpenAI 公式情報（2026 時点の調査）に基づく**設計前提**:

- API 経由のデータは、既定でモデル学習には使われない（OpenAI のデータ利用ポリシー）。ただし最新の規約で都度確認する。
- 既定では、abuse 監視のためにリクエスト内容が**最大 30 日程度**保持され得る（法令・安全のため延長され得る）。
- **Zero Data Retention (ZDR) / Modified Abuse Monitoring** は、対象顧客が**事前承認**を受けた場合に、abuse 監視ログから顧客コンテンツを除外できる仕組み。**セルフサービスのトグルではなく**、OpenAI への申請・承認・対象エンドポイントの確認が必要。
- ZDR 下でも、CSAM 検出時など一部は手動レビュー用に保持される例外がある。
- Realtime / 音声系エンドポイントが ZDR 対象かは、申請時に OpenAI へ確認する（対象は変動し得る）。

> したがって UI / docs では「アプリ側は本文を保存・ログ化しない」と書き、「OpenAI 側でも一切保持されない」とは**書かない**。「API データは学習に使われない前提で、abuse 監視の一時保持は ZDR / Modified Abuse Monitoring の承認で除外を申請中／済み」のように、条件付きで正確に書く。

## 6.1 H-3 実施手順（人間・会議内容を扱うため要実施）

会議の音声を OpenAI に送るため、データ保持の実態を確認しておく。以下を上から順に。

1. **学習利用の確認（既定でオフのはず）**
   - OpenAI ダッシュボード → Settings → Data controls（組織/プロジェクト）。
   - API 経由データがモデル学習に使われない設定/方針であることを確認（API は既定で学習に不使用）。
2. **保持期間の理解**
   - 既定では abuse 監視のためリクエストが**最大30日程度**保持され得る（法令/安全で延長例外あり）。これは「アプリが保存する」のではなく**OpenAI 側**の話。
3. **ZDR / Modified Abuse Monitoring の要否判断**
   - より厳格にしたい場合、OpenAI に **Zero Data Retention** または **Modified Abuse Monitoring** を申請（**セルフサービス不可・要承認**）。
   - 申請時に **Realtime / `gpt-realtime-translate` / `gpt-realtime-whisper` が対象エンドポイントか**を必ず確認（対象は変動し得る）。
   - 個人利用で会議の機微度が高くなければ「既定（30日 abuse 保持・学習不使用）」で許容するのも選択肢。**判断を本ファイルに記録する**。
4. **アプリ側の保証の再確認（実施済み・コードで担保）**
   - 本アプリは音声/transcript/翻訳本文を保存せず、ログ/ストレージにも出さない（security-review #2 で確認済み）。
   - Safety-Identifier は平文メールでなくハッシュを送信。
5. **結論を記録**（例: 「ZDR 申請済み/未申請、既定保持を許容、対象に realtime 含む/含まない」）。

> 表現は断定しない: UI/説明では「アプリ側は保存・ログ化しない」「OpenAI 側は学習不使用＋（申請状況に応じ）ZDR/Modified Abuse Monitoring」と条件付きで書く。
