# docs/agent-strategy.md — Agent 戦略・モデル使い分け・ゲート

高思考モデルは「設計・判断・分解・レビュー方針」に集中し、実装は軽量 Agent に渡す。各 Agent には**最小コンテキスト**だけ渡す。

## F-1. Agent 役割分担

### 1) Strategic Planner Agent（高思考）
- 役割: 要件分解、ADR 判断、Gate 通過可否の方針、リスク評価、バックログ再計画。
- モデル: 高思考。
- 入力: `context-summary.md` + 対象 docs + 課題の要約。**全履歴は渡さない**。
- 出力: ADR 案、チケット分解、受け入れ条件、レビュー観点。
- 禁止: 実装コードの量産、独断での方針変更（人間承認が要る項目）。
- 完了条件: チケットが受け入れ条件付きで `TASKS.md` に並ぶ / ADR が出る。

### 2) Lightweight Implementation Agent（軽量〜中）
- 役割: 1 チケットの実装。
- モデル: 軽量〜中程度。
- 入力: `context-summary.md` + 対象チケット + 触る範囲の docs/ファイル。
- 出力: 差分コード、最小テスト、`TASKS.md` 更新。
- 禁止: 範囲外実装、新規依存の無断追加、アーキ変更、本文ログ。
- 完了条件: 受け入れ条件 + 該当セキュリティチェック + lint/typecheck/test green。

### 3) Test Agent（軽量〜中）
- 役割: 受け入れ条件に対応するテスト作成・実行、本文非ログ/非保存の検証。
- 入力: チケットの受け入れ条件 + 対象コード。
- 出力: テストコード、結果サマリ（本文を含めない）。
- 禁止: 実データ使用（架空短文のみ）、テストのために本番設定を緩める。
- 完了条件: 受け入れ条件を網羅、green。

### 4) Security Review Agent（中〜高）
- 役割: `docs/security.md` チェックリストに対する差分レビュー。
- 入力: 差分 + `security.md` + `privacy-data-handling.md`。
- 出力: 指摘（重大度付き）、必須修正、合否。
- 禁止: 合格の安易な追認。曖昧は不合格側に倒す。
- 完了条件: Critical/High 指摘ゼロ、チェックリスト該当項目 ✅。

### 5) Documentation Agent（軽量）
- 役割: `context-summary.md` / `TASKS.md` / ADR / docs の同期更新。
- 入力: 直近の変更要約。
- 出力: 簡潔な docs 差分。
- 禁止: 冗長化、断定的なデータ保持表現、秘密の記載。
- 完了条件: docs と実装が一致、context-summary が最新。

### 6) Release Readiness Agent（中〜高）
- 役割: Gate 7 のリリース判定。全チェックリスト・受け入れ条件・残余リスクの確認。
- 入力: 受け入れ条件、`security.md`/`privacy-data-handling.md` チェック結果、risks。
- 出力: 判定（GO / NO-GO）+ 残課題。
- 禁止: 未確認項目を GO にする。
- 完了条件: MVP DoD 充足、人間最終承認待ちの整理完了。

## F-2. モデル使い分け方針

- **高思考**: アーキ判断、ADR、セキュリティ設計、分解、リリース判定、難バグの原因設計。
- **中程度**: 標準的な実装、セキュリティレビュー、テスト設計。
- **軽量**: 定型実装、docs 更新、context 要約、軽微修正。
- **人間確認必須**: 認証方式/デプロイ先/モデル/データフロー/保持・ログ方針の変更、Gate 通過、ZDR 申請、本番 secrets。
- **Agent に任せてよい**: チケット範囲の実装・テスト・docs 同期・レビュー。
- **Agent に任せない**: 実 secrets 操作、本番デプロイ承認、規約/プライバシー表現の最終確定、実データ取り扱い。

## F-3. トークンコスト最適化

- **毎回渡す最小コンテキスト**: `docs/context-summary.md` + 対象チケット + 触る docs/ファイルのみ。
- `context-summary.md`: 最新決定・実装状況・次チケットを 1 画面に保つ。変更のたび Documentation Agent が更新。
- `TASKS.md`: チケット + ステータス + 受け入れ条件。これを単一の真実とする。
- ADR: 重要判断のみ短く記録（`docs/adr/`）。意思決定の根拠を再説明せず ADR 参照で済ます。
- 要件変更時: 「再計画プロンプト」で差分のみ反映 → context-summary と TASKS に反映。
- 要約ルール: 過去の対話全文を渡さず、決定事項の箇条書きだけ渡す。
- 入出力テンプレートは `docs/agent-prompts.md`。
- **1 回の実行でやってよい**: 1 チケット相当の実装/テスト/docs 同期。
- **やってはいけない**: 複数 Gate 跨ぎ、大規模リファクタ、無関係ファイル変更、アーキ変更、依存大量追加。

## F-4. 自律開発フロー（ゲート）

各 Gate: 目的 / 実装 / 受け入れ / テスト / セキュリティ確認 / 次へ進む条件 / 差し戻し条件。

### Gate 0: 要件・制約確定
- 目的: 本ドキュメント群の確定。
- 実装: docs 一式・AGENTS・TASKS。
- 受け入れ: 要件/制約/データ方針が docs に揃う。
- 確認: 非交渉制約が AGENTS.md に明記。
- 次へ: 人間が方針を承認。
- 差し戻し: 制約矛盾・未決の核心事項あり。

### Gate 1: 認証土台
- 目的: OAuth + allowlist。
- 実装: Auth.js 設定、middleware ガード、allowlist 照合。
- 受け入れ: 許可メールのみログイン可、未認証は `/translate`/API 拒否。
- テスト: 許可/不許可/未認証の 3 ケース。
- 確認: cookie 設定、メール平文非ログ。
- 次へ: 認証テスト green。
- 差し戻し: 許可外がログインできる/未認証が通る。

### Gate 2: client secret 発行 API
- 目的: 短命トークン発行。
- 実装: `POST /api/realtime/client-secret`（認証+allowlist+rate、Safety-Id ハッシュ、TTL 短）。
- 受け入れ: 標準キーを返さない、未認証/許可外は 401/403、超過で 429。
- テスト: レスポンスに `sk-` が無い・`ek_` のみ。認可分岐。
- 確認: §security 10/11。
- 次へ: API テスト green。
- 差し戻し: 標準キー露出・認可漏れ。

### Gate 3: WebRTC 翻訳 UI
- 目的: 実翻訳。
- 実装: getUserMedia、PeerConnection、data channel、字幕表示、Start/Stop/Clear/unload。
- 受け入れ: 英語→日本語字幕がリアルタイム表示、Stop でマイク解放。
- テスト: 状態遷移、解放、再接続（手動 + 可能な範囲で自動）。
- 確認: delta を console/log/storage に残さない。
- 次へ: 実機/PC で字幕表示・解放確認。
- 差し戻し: 解放されない/本文混入。

### Gate 4: ログ・データ保持確認
- 目的: 非保存/非ログの実証。
- 実装: ログ正規化、storage 未使用確認。
- 受け入れ: 本文がネットワーク以外に残らない。
- テスト: ログ grep、devtools の storage 確認、ビルド grep。
- 確認: `privacy-data-handling.md` の確認事項、ZDR 状況。
- 次へ: 本文残存ゼロ。
- 差し戻し: 本文がどこかに残る。

### Gate 5: セキュリティレビュー
- 目的: チェックリスト合格。
- 実装: 指摘修正。
- 受け入れ: Critical/High ゼロ、`security.md` 該当 ✅、`npm audit` 対応。
- 次へ: Security Review Agent + 人間が合格判定。
- 差し戻し: 重大指摘残存。

### Gate 6: iPhone 実機確認
- 目的: Safari 実機動作。
- 受け入れ: マイク許可、字幕表示、解放、復帰再接続。
- 確認: secure context、権限導線。
- 次へ: 実機 OK。
- 差し戻し: 実機で動かない/解放されない。

### Gate 7: MVP リリース判定
- 目的: GO/NO-GO。
- 受け入れ: 全受け入れ条件 + 全 Gate 通過 + 残余リスク許容 + 人間承認。
- 次へ: 本番デプロイ（人間が実行）。
- 差し戻し: 未充足項目あり。
